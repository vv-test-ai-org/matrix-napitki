# Матрица ассортимента «Напитки + Алкоголь» — симулятор

Еженедельно пересобираемая HTML-матрица: прогноз SKU по месяцам (12 мес.), поканальные разрезы, редактирование ячеек/дат с пересчётом, журнал правок. Заказчик — продакт пути Напитки.

Текущая версия — `out/Матрица_Напитки_Алкоголь_1С_2026-10-26.html` (данные 1С/Superset на 23.10.2026, трекеры по API). Опубликована: https://vv-test-ai-org.github.io/matrix-napitki/ (репозиторий `vv-test-ai-org/matrix-napitki`, владелец — аккаунт vv-ai-dev-test), доступ по коду — см. «Публикация».

Сборка одной командой: `python3 publish.py` (Superset → Трекер → build → шифрование → gh-pages). Вручную: (1) `python3 fetch_superset.py` (запросы из `sql/*.sql`, креды в `.env`); (2) `python3 fetch_tracker.py`; (3) поправить `DATA_DT`/`week` в `build.py` на дату выгрузки; (4) `python3 build.py out/…html`. История решений: `docs/Задачи_доработки_матрицы_по_встрече_14-10.md`, `docs/Задачи_доработки_матрицы_по_встрече_23-10.md` (там же статус каждой задачи).

## Правила, принятые 26.10.2026
- **База матрицы — SKU с продажами за рассматриваемый период**: продажи за 3 полных месяца (`sales_tail.csv`) ∪ факт матрицы ТТ за 4 недели (`channel_ch.csv`). Характеристики 1С без продаж за период в матрицу не попадают (кроме строк с датой остановки — они нужны для вывода). SKU с продажами, которых нет в `har_kontr.csv`, добавляются с источником «Продажи (ClickHouse)» и флагом «проверьте справочник».
- **Новинки — только из трекера NEWPRODUCT**. Карточки 1С со статусом «Новая» без продаж в матрицу не входят; если у такой карточки есть продажи — это текущий ассортимент (с флагом).

## Правила, принятые 23.10.2026
- **Новинки из трекера** — только статусы от «Согласование наименования» до «Открыть SKU» (список `TAKE` в `build.py`). Беклог, Отложено, Торг, Согласование КП, дегустация, В продаже, Постоянный ассортимент, Отказ, Закрыт — не берутся: то, что продаётся, уже есть в матрице через 1С. Со статуса «Заведение в ЛК» карточка должна быть в 1С — ищется по «Наименование в 1С», иначе флаг.
- **Название новинки** — «Наименование в 1С», если присвоено; рабочее название из трекера остаётся в подсказке.
- **Хвост выработки** — отдельная ячейка «хвост» после месяца остановки, 1 мес. (первый этап); оценка по продажам (остаток ÷ средние продажи за 3 мес.) показывается в столбце, если отличается. В своде переключатель «с хвостом выработки». Формулу из трекера вывода (Костя Васянин) подключить, когда появится.
- **In-out новинки** — поле «Дата остановки / окончания» редактируется в строке и обрезает месяцы; в выгрузке трекера даты пока нет.
- **Журнал правок** — отмена по одной (↺), сортировка по позиции, фильтр по полю и поиск.
- Колонки позиций: Подгруппа → Товар (обе закреплены). Строка температуры убрана.

## Сборка
```
python3 fetch_tracker.py                                   # трекер вывода → data/withdraw.csv
python3 build.py out/Матрица_Напитки_Алкоголь_<дата>.html
```
Нужны pandas, openpyxl и CLI `ya-tracker` (`~/bin/ya-tracker`, конфиг `~/.ya-tracker`, логин aicenter1). Правила сборки — в `docs/ТЗ_ВВчат_матрица_ассортимента_Напитки_Алкоголь.md`, SQL для Superset — в `docs/Superset_источники_для_матрицы_Напитки_Алкоголь.md`.

## Трекер вывода SKUWITHDRAW (подключён 23.10.2026)
- Берём только задачи с доски «Вывод товаров из ассортимента; Путь Напитки» (остальное в очереди — блины другого пути и тесты), без статусов «Закрыт» и «Беклог».
- Статусы API → доска: `open`=На вывод, `vRaboteUTehnologa`=В работе у технолога, `naSoglasovanii`=На согласовании, `notagreed`=Не согласовано технологом, `received`=Получен ответ от поставщика, `onpause`=Планируется возвращение в сезон.
- Поля (локальные, префикс `6a68974352d91521d25f3d47--`): `idTov`, `plannedWithdrawalDate`, `dateOfProductWithdrawalstopInc`, `outputType` (Сезонный / Вывод из ассортимента), `renewalDate`, `renewalStatus`, `openingDateForOrders`, `theRestLabelForTheNextSeason`, `labelRemainder`, `suppliersName`, `SKUCharacteristicStatus`.
- Как используется в `build.py`:
  - **возобновление** = есть `renewalDate` или статус «Планируется возвращение в сезон»; сопоставление с 1С по `idTov`, иначе по названию; без даты — строка остаётся с флагом «нет даты возобновления в трекере»; дата в прошлом — флаг «дата возобновления уже прошла»;
  - **плановый вывод** = `plannedWithdrawalDate` у задачи без возобновления: если в 1С даты остановки нет — берём её как план (серая зона, `conf=0`), если есть и отличается — флаг с обеими датами;
  - ключ задачи попадает в колонку «ID / ключ», остаток этикетки на следующий сезон — во флаги.
## Трекер новинок NEWPRODUCT (подключён 23.10.2026, после выдачи доступа)
- Очередь общая для всех путей (больше 10 000 задач, API не отдаёт всё разом) — выгружаем только доску 4306: `Queue: NEWPRODUCT AND Boards: 4306` (1043 задачи на 23.10).
- Поля → колонки `new.csv`: `agreedName` → «Наименование в 1С» (присвоенное), `productName` → «Рабочее название», `summary` → «Название», `targetInputDate` → «Дата ввода» (+ «Месяц ввода»/«Год запуска» для совместимости), `lastSaleDate` (локальное, префикс `690af1a3b6c8771eb8cf1e6f--`) → «Последняя дата продажи» (конец in-out), `clusterName` → «Кластер» (география поставки), `inaut`, `aSubgroupOfProducts`, `productCategorynewItems`, `suppliers`/`suppliersId`, `shelf`/`shelfOnline2`, `theStatusInLc`/`dateOfTheStatusInLc`, `theItemsCharacteristicStatus`, `idFromTheLc`.
- Как используется в `build.py`: статусы по списку `TAKE`; дата ввода — «Дата ввода»; in-out обрезается «Последней датой продажи» (если её нет — флаг и ручное поле в HTML); канал — из «Кластер» (есть дарксторы/«Сеть» → офф+онл, только «Дарки» → онлайн, только Вайты/Шмели → оффлайн), иначе правило по полкам/подгруппе; если в «Наименовании в 1С» впереди стоит ID («94 374 Сок…»), он берётся как ID 1С.
  Берём статусы: Согласование наименования, Приложить макет, Согласование ДС, Заведение в ЛК, Статус на ЛК, Согласование КДП, Согласование этикетки, Готов к старту, Планирование первого заказа, Открыть SKU.
  Не берём: Беклог, Отложено, Доработки по итогам дегустации, Согласовано по вкусу, Торг, Согласование КП, В продаже, Постоянный ассортимент, Выведена, Отказ, Закрыт.
- 1С: статус характеристики. «На вывод»/«Приостановлена» + «Выведена» — дата остановки прошла; + «Активная» — будущая дата остановки. Реализовано в `build.py` (`decide()`).
- Зеркала Трекера в Superset нет (YTRACKER содержит только SERVICEDESK), поэтому путь — только API через `ya-tracker`.

## Публикация (GitHub Pages, доступ по коду)
Репозиторий публичный (Pages на бесплатном плане), поэтому в него попадает **только код**: `build.py`, `template.html`, `fetch_*.py`, `publish.py`, `site_loader.html`, workflow. Данные (`data/`), SQL с внутренними именами таблиц (`sql/`), документы (`docs/`), `.env` и код доступа (`.pages-code`) — в `.gitignore`.

- `publish.py` собирает HTML, шифрует его кодом доступа (PBKDF2-SHA256 250k → AES-256-GCM) и кладёт `site/index.html` в ветку `gh-pages`. На странице — поле ввода кода (расшифровка в браузере, код никуда не уходит), галочка «запомнить» и кнопка **«Обновить данные ↗»**, которая открывает запуск workflow «Обновить матрицу» (Run workflow) — нужен аккаунт GitHub с правом на репозиторий.
- Workflow `.github/workflows/rebuild.yml` (кнопка + понедельник 07:00 МСК) выполняется на **self-hosted runner** внутри контура: `bash runner/setup.sh` ставит его как сервис на этом Mac (нужны `gh` и доступ в интернет). Раннер делает `git pull` и `python3 publish.py` в локальной копии проекта (`MATRIX_HOME`), где лежат `.env` и `data/`.
- Код доступа: `.pages-code` (создаётся при первой публикации) или `PAGES_CODE` в `.env`. Смена кода = поправить файл и перезапустить `publish.py`.
- Superset: `fetch_superset.py` ходит в SQL Lab по REST (`POST /api/v1/sqllab/execute/`), креды — `SUPERSET_URL/USER/PASSWORD/PROVIDER` из `.env` (см. `.env.example`).
